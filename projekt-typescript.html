Lernperiode 8

TypeScript vertiefen

Eine Lernperiode ohne grosses Endprodukt, dafür mit einem klaren Ziel: TypeScript so weit verstehen, dass ich es jemand anderem erklären kann. Herausgekommen ist eine kleine Task-App und ein Tutorial, mit dem sie sich nachbauen lässt.

Ziel

JavaScript kannte ich aus früheren Modulen. TypeScript hatte ich noch nicht wirklich genutzt. In dieser Lernperiode wollte ich verstehen, was das Typsystem tatsächlich für mich übernimmt und wo es mich zwingt, vorher nachzudenken.

Als Prüfstein habe ich mir vorgenommen, das Gelernte als Tutorial aufzuschreiben. Erklären zwingt zu Genauigkeit: Was ich nur halb verstanden habe, merke ich spätestens beim Schreiben.

Technologien

TypeScript · DOM-API · tsc · HTML · Markdown

Inhalte

Beispiel ist eine Task-App: Aufgaben mit Titel und Priorität erfassen, in einer Liste anzeigen und als erledigt markieren. Behandelt werden dabei:

  • Union Types: eine Priorität darf nur „Niedrig“, „Mittel“ oder „Hoch“ sein, nichts anderes
  • Interfaces: die Form eines Task-Objekts einmal festlegen, damit jede Task gleich aufgebaut ist
  • Typisierte Arrays: eine Liste, die ausschliesslich Task-Objekte aufnimmt
  • Type Assertion: dem Compiler mitteilen, welches HTML-Element hinter einer ID steckt
  • Funktionen mit Rückgabetyp: auch dann, wenn nichts zurückkommt

Vorgehen

Statt ein Konzept nach dem anderen abzuarbeiten, habe ich mir zuerst die App überlegt und dann geschaut, welches Sprachmittel welches Problem löst. Die Priorität einer Task war der beste Aufhänger: Mit einem einfachen string wäre jeder Tippfehler durchgegangen, mit einem Union Type meldet sich der Compiler sofort.

Beim Schreiben des Tutorials habe ich die Reihenfolge mehrfach umgestellt. Erklärungen, die für mich logisch waren, setzten Wissen voraus, das an der Stelle noch gar nicht da war. Am Ende steht jedes Konzept dort, wo es im Aufbau der App zum ersten Mal gebraucht wird.

Stolpersteine

  • Der häufigste Fehler: vergessen, die TypeScript-Datei zu kompilieren. Der Browser führt weiterhin den alten JavaScript-Stand aus, und man sucht den Fehler an der falschen Stelle.
  • Type Assertion beim Zugriff auf HTML-Elemente. In JavaScript geht es ohne. TypeScript will wissen, ob es ein Input-, Select- oder Button-Element ist.
  • Selbstverständliches zu erklären ist schwerer als gedacht. Der Text war in der ersten Fassung eine Aneinanderreihung von Codeschnipseln ohne Zusammenhang.

Was ich gelernt habe

  • Union Types statt string für feste Werte. Ein Tippfehler bei der Priorität fällt beim Kompilieren auf, nicht erst zur Laufzeit.
  • Interfaces legen die Struktur eines Objekts fest. Fehlt ein Feld oder hat es den falschen Typ, meldet es der Compiler.
  • getElementById gibt ein HTMLElement zurück. Für .value braucht es eine Type Assertion auf HTMLInputElement.
  • Rückgabetyp void bei Funktionen, die nichts zurückgeben.
  • TypeScript läuft nicht direkt im Browser. Ohne tsc vor jedem Test bleibt der alte JavaScript-Stand aktiv.
